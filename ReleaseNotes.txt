7-Zip-JBinding Release Notes
============================

Known issues
------------

    * None currently tracked.
      (CVE-2024-11477, the 7-Zip Zstandard decompression issue affecting 23.01-2.x, is resolved
      as of 26.06-2.3 - the bundled engine now postdates the upstream fix in 7-Zip 24.07.)


Main features of 26.06-2.4 (application class loaders: Spring Boot, servlet containers, OSGi)

    * Fixed: JVM abort when 7-Zip-JBinding is loaded by a class loader the system
      class loader can't see - Spring Boot fat jars, servlet containers (Tomcat,
      Jetty), OSGi, IDE plug-ins and similar hosts (issues #7, #15, #35). 7-Zip's
      encoder and decoder threads have no Java frames, so a JNI class lookup on
      them went through the system class loader, failed and aborted the JVM
      ("Class net/sf/sevenzipjbinding/IInStream not found"). Hit by 7z compression
      with default settings from about 1 MB of data and by extraction of 7z
      archives with several LZMA2 blocks. All Java classes used by the native code
      are now resolved once at initialization, on the Java thread.

    * Fixed: 7-Zip's worker threads had no context class loader (null). Callbacks
      and streams running on them now see the context class loader of the thread
      that called 7-Zip-JBinding (open, extract, update), so ServiceLoader,
      resource lookups and framework code (Spring beans, OSGi services) work from
      every callback.

    * Docs: the callback and stream interfaces document that 7-Zip may call them
      on its own worker threads and which context class loader they see.

    * Tests: a Spring Boot 4 test application (test/spring-boot-test) packaged as
      a fat jar now runs on the build host in every test campaign; it reproduces
      the abort on 26.06-2.3 and passes with this release.

    * Fixed: JVM abort when a 7z, zip or tar archive was written to an output
      stream that implements only ISequentialOutStream (no seek()). Every output
      stream was wrapped as a seekable IOutStream, so 7-Zip's first Seek() looked
      up seek() on the Java class and the binding aborted the JVM ("Method not
      found: seek()"). The wrapper now follows the Java type: zip, tar, gzip,
      bzip2 and xz are written sequentially, 7z fails with a SevenZipException
      stating that it needs a seekable IOutStream (RandomAccessFileOutStream,
      ByteArrayStream). Regression test: CompressSequentialOutStreamTest.

    * Fixed: JVM crash when one archive was used from several threads at the
      same time - item properties read by one thread (a GUI renderer, a
      scanner) while another thread extracts or closes the archive (issues
      #70, #62: SIGSEGV or "double free or corruption" in
      nativeGetStringProperty). The native library now uses 7-Zip's atomic
      reference counts, and close() is serialized against running calls: it
      waits for them, later calls throw SevenZipException("InArchive closed"),
      and a close() from a callback of the same archive throws instead of
      deadlocking. Reading properties from several threads at once is
      supported; extraction and update still run one at a time per archive.
      Regression test: ConcurrentCloseTest.

    * New: set the dictionary size of 7z archives independently of the
      compression level (IOutFeatureSetDictionarySize.setDictionarySize(long),
      on IOutCreateArchive7z and IOutUpdateArchive7z; issue #61, pull request
      #101 by drakeet). A smaller dictionary needs much less memory to compress
      and to extract and, with LZMA2, splits one large file into more blocks
      for the parallel compression. Reported for a 190 MB database at level 5
      with a 1 MiB dictionary: 28 s -> 6 s and +987 MB -> +284 MB on a 20-thread
      desktop, 56 s -> 23 s and +878 MB -> +64 MB on a phone, archive 46 -> 52 MB.

    * Fixed: output properties set on an archive object and then reset to the
      defaults before a second archive (for example setSolid(false), then
      setSolid(true)) still applied to the second archive (pull request #101).

    * Fixed: hybrid ISO-9660/UDF images (DVD images with files of 4 GiB and
      more) opened as ISO and showed sizes modulo 4 GiB (a 4.00 GB file as
      8 MB). Autodetection now tries UDF before ISO, as 7-Zip does (issue #55).

    * New: PropID.PATH_BYTES returns the stored, undecoded name bytes of a Zip
      item as byte[], so names in a legacy code page (GBK, Shift_JIS, CP437)
      can be decoded by the caller: strictly as UTF-8 first, with the legacy
      charset if that fails (issue #56; based on pull request #36 by Ethan
      Roseman). Other formats return null.

    * New: ItemType.of(inArchive, index) tells whether an item is a regular
      file, directory, symbolic link, hard link, reparse point, device, fifo
      or socket, and ItemType.unixMode() gives the Unix mode wherever the
      format stores one (POSIX_ATTRIB, or the upper 16 bits of ATTRIBUTES).
      UnixMode and WindowsAttributes hold the named bit constants (issue #91).

    * New: IReusableBufferOutStream - implement it instead of
      ISequentialOutStream and 7-Zip-JBinding hands every chunk over in one
      reused byte[] (write(buffer, offset, length)) instead of allocating a
      new array per chunk; useful for very large extractions and small heaps
      (issue #69).

    * Docs: IOutCreateArchive.createArchive() and IOutUpdateArchive.updateItems()
      state which formats need a seekable output stream and that 7z may reorder
      items on update (unchanged items keep their solid block).

    * Java API and binaries: no API changes; binary and source compatible with
      26.06-2.3. Maven coordinates unchanged.


Main features of 26.06-2.3 (engine upgrade to 7-Zip 26.06)

    * Upgraded the bundled 7-Zip engine from 23.01 to 26.06 (released 2026-11-06),
      via the vendored-engine workflow. Brings the upstream format, decoder and
      bug fixes accumulated since 23.01, including extraction of
      Zstandard-compressed ZIP entries, the bug and vulnerability fixes of 7-Zip
      26.04 to 26.06, improved unpacking of Z archives and Mach-O files (26.05)
      and improved support for split files created by the Linux "split" utility
      (26.06).

    * Security: resolves CVE-2024-11477 (7-Zip Zstandard decompression, severity
      HIGH, CVSS 7.8). The 26.06 engine postdates the upstream fix released in
      7-Zip 24.07, so the Zstandard known-issue from 23.01-2.x no longer applies.
      Tracking: https://github.com/borisbrodski/sevenzipjbinding/issues/72

    * New platform: FreeBSD (amd64). A native FreeBSD x86_64 library (platform
      'FreeBSD-amd64'), built and tested on FreeBSD 14 (clang + OpenJDK), passing
      the full suite. Runtime auto-detection selects it on a native FreeBSD JVM
      (os.name=FreeBSD); it is also included in the -all-platforms jar. (Note: on
      the Linux compatibility layer the existing Linux-amd64 library also works.)

    * New platform: Windows on Arm (arm64). A native aarch64 Windows library
      (platform 'Windows-arm64'), built with the llvm-mingw GCC-style toolchain
      and included in the AllWindows and AllPlatforms jars. The -all-platforms
      jar auto-detects and loads it on a native arm64 Windows JVM.

    * macOS: per-architecture artifacts. BREAKING for Maven/Gradle users on macOS:
        - sevenzipjbinding-all-mac     universal library (Intel + Apple Silicon); the
                                       macOS library inside -all-platforms
        - sevenzipjbinding-mac-arm64   Apple Silicon only (smaller)
        - sevenzipjbinding-mac-x86_64  Intel only (smaller)
      The universal artifact sevenzipjbinding-mac is no longer published: depend
      on -all-mac instead. sevenzipjbinding-mac-x86_64 was an alias of the
      universal library and is now Intel-only - on Apple Silicon switch to
      -all-mac or -mac-arm64. -all-platforms users are not affected.

    * Documentation: new "Extraction masterclass" page - fast, safe and correct
      extraction (one pass over solid archives, a byte-only callback, path
      traversal/link/nameless-entry protection, complete error accounting) with
      complete, tested examples; new snippets for extracting to a folder and for
      wrapped archives (.tar.gz).

    * Distribution: release zips no longer include website.zip (an offline copy
      of the old web site). Documentation: https://sevenzipjbind.sourceforge.net/
      JavaDoc still ships inside every zip as javadoc.zip. Every zip now also
      contains License.txt (the 7-Zip engine license: LGPL with the unRAR
      restriction, and BSD licenses for a few decoder files).

    * New item properties: PropID.USER_ID, GROUP_ID (Tar/Cpio owner ids),
      DEVICE_MAJOR/DEVICE_MINOR (Tar device entries), DEV_MAJOR/DEV_MINOR
      (Cpio), CHANGE_TIME (NTFS/UDF), ARC_FILE_NAME, IS_HASH - the engine
      reported them before, but Java showed them as UNKNOWN. New
      NFileTimeType.NANOSECONDS (1 ns time precision).

    * Fixed: a native library that can't be copied into the temporary
      directory is now reported as the declared
      SevenZipNativeInitializationException (and via
      SevenZip.getLastInitializationException()), not a plain RuntimeException.
      A partially written library file is removed.

    * Fixed (also affects 23.01-2.2): the JVM could abort during extraction
      with "FATAL ERROR: Method not found: reportExtractResult()". The native
      code looked up IArchiveExtractCallback.reportExtractResult() with a
      malformed JNI signature, so the call failed whenever the engine used it -
      e.g. when a 7z solid block fails to decode after all requested files were
      written (seen with a wrong or missing password). Both extract() and
      extractSlow() were affected. The block-level result now reaches
      reportExtractResult() (BLOCK_INDEX, DATAERROR) and extraction continues.

    * Fixed bug #77 (also affects 23.01-2.2 and all previous releases): 7z compression
      features set together canceled each other out - of compression level, header
      encryption, thread count and solid settings only the last applied one took
      effect. Security-relevant: setHeaderEncryption(true) was silently lost as soon as
      the thread count or a solid setting was set too, so the file names stayed
      readable without the password. Archives created with several of these features
      now get all of them - expect different sizes than before. Fixed by mrjo118
      (pull request #93). https://github.com/borisbrodski/sevenzipjbinding/issues/77

    * Fixed crashes of other C++ code in the same process (Linux; also affects 23.01-2.2
      and earlier): the native library exported its statically linked C++ runtime,
      whose process-wide (GNU-unique) symbols clashed with the system libstdc++.so.6
      loaded later, e.g. by another JNI library. The Linux and FreeBSD libraries now
      export only their JNI entry points and are 16-35% smaller, depending on the
      platform; system requirements are unchanged. Contributed by Alexandru Sclearuc
      (pull request #95).

    * Fixed JNI reference handling (also affects 23.01-2.2 and earlier): multithreaded 7z
      compression used a thread-local JNI reference on 7-Zip's worker threads. HotSpot
      tolerates it, but JVMs that check references (e.g. -Xcheck:jni) abort. Per-item
      local reference leaks in the extract, update and volume callbacks are fixed too
      (follow-up to pull request #66), and boxing property values from native code
      now checks for a pending exception as the JNI specification requires.

    * Fixed regression of 23.01-2.2: split archives (x.7z.001, x.7z.002, ...) couldn't be
      opened with an IArchiveOpenVolumeCallback - opening failed with "returns stream=null
      for volume 'x.7z.005'" after the last volume.

    * Java API: additions only, binary and source compatible with 23.01-2.2
      (checked with japicmp): existing Java code is unaffected (see the macOS
      artifact change above for Maven/Gradle coordinates). One exception: the
      internal class impl.OutArchiveImpl lost its four protected native setters
      (bug #77 fix), which matters only for code subclassing it. The complete build
      + runtime test matrix is green on the new engine (Linux glibc & musl on
      arm/x86, Windows x86/x64/arm64, macOS arm64 & x86_64, FreeBSD amd64).


Main features of 23.01-2.2 (Release, extraction/compression/update, cross-platform, based on 7-Zip 23.01)

    * Bind 7-Zip 23.01, In-memory archive extraction/creation/update

    * Extraction of
        - 7z, Arj, BZip2, Cab, Chm, Cpio, Ar/A/Lib/Deb, Fat, GZip, HFS, Iso,
          Lzh, Lzma, Nsis, Ntfs, Rar, Rpm, Split, Tar, Udf, Wim, Xar, Xz, Z, Zip

        - Archive format auto detection
        - Support for password-protected and multi-volume (split) archives
        - Full featured and simplified extraction interfaces

    * Compression & update of
        - 7z, Zip, Tar, GZip, BZip2, Xz
        - Convenient archive format specific and generic compression APIs
        - Password protected archives (7z, zip) with encrypted archive headers (7z only)
        
    * 7-Zip-JBinding requires Java 8 or higher

    * Cross-platform. Binaries available for
        - Windows 32/64
        - Linux 32/64 (glibc)
        - Linux ARM (glibc):
			* ARMv5 (armel, soft-float)
			* ARMv6 (Raspberry Pi 1/Zero, hard-float)
			* ARMv7 (armhf)
			* ARM64
        - Linux musl (Alpine): amd64, ARM64, ARMv7
        - macOS: single universal binary for Intel (x86_64) and
          Apple Silicon (arm64)

    * Multi-platform distributions (with runtime platform auto-detection:
      OS/architecture, ARM level + float ABI, glibc vs musl):
        - AllWindows   - Win32 + Win64
        - AllPlatforms - ALL 12 platforms in one jar (Windows, Linux glibc
                         including ARM, Linux musl, macOS universal)

    * JavaDoc + Snippets (see documentation on the web: sevenzipjbind.sf.net)

        * 8845 JUnit tests:
            - Initialization
            - All extraction methods
            - Compression
            - Unicode support

    * Available on the Maven Central (a week after the official release)
        <dependency>
            <groupId>net.sf.sevenzipjbinding</groupId>
            <artifactId>sevenzipjbinding</artifactId>
            <version>23.01-2.2</version>
        </dependency>
        <dependency>
            <groupId>net.sf.sevenzipjbinding</groupId>
            <artifactId>sevenzipjbinding-all-platforms</artifactId>
            <version>23.01-2.2</version>
        </dependency>
